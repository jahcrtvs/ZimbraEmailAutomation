# Local AI with consented cloud fallback: design

Date: 2026-10-13. Supersedes the "AI provider" parts of `2026-10-09-daily-digest-electron-design.md`. Everything else in that spec still holds (prepare-only Zimbra, no Zimbra password, local JSON storage, schedule owned by the main process).

## Goal

The default way to turn rough notes into formal sentences is a model running on the user's own computer, through Ollama. Gemini and Groq stay, but only as one optional fallback that is used when the local model fails, with the user's knowledge and with the notes sanitised first.

## Decisions (agreed 2026-10-13)

| # | Decision |
|---|---|
| Runtime | Ollama (not bundled). Reached through an OpenAI-compatible base URL, default `http://localhost:11434/v1`. LM Studio or llama-server should work by changing the URL; only Ollama is documented as supported. |
| Default model | `qwen2.5:3b-instruct`. README suggests `qwen2.5:7b-instruct` for machines with 16 GB RAM or a GPU. Model name is free text. |
| Local failure | Ollama unreachable, model not installed, timeout (120 s), invalid JSON after one retry, empty result, or a server error. The alert names the cause. |
| Fallback | One provider chosen in Settings: None, Groq (default choice) or Gemini. No chain, so one run never reaches two vendors. |
| Consent | Default: ask each time, with a preview of the exact text. Opt-in setting "use automatically". Either way the finished digest carries a persistent "Generated by X (cloud)" label. |
| Sanitising | Cloud path only. Local path receives the raw notes. |
| Audit | Local log of every cloud send: time, provider, reason, character count. Never the content. |
| Plain template | If local fails and the cloud is unavailable, declined, blocked or fails, the digest is built with the built-in text rules and a banner says why. |
| Onboarding | Settings shows local status (server down / model missing / ready) with the exact command to run. README has the full guide. |
| Cloud model names | A local model name ending in `-cloud` runs on Ollama's servers. Warn, do not block. |
| Non-local URL | A base URL that is not loopback gets a warning (raw notes go to that host). Not blocked, since a LAN server is legitimate. |

## Behaviour

### Generate (mode `auto`)

1. Build the prompt from the raw notes and call the local model. Timeout 120 s. Ask for JSON.
2. If the reply is not valid JSON, ask once more. A second failure is a `BAD_REPLY` failure.
3. On success, render the template. Source is `local`.
4. On failure, record `{code, message}` and look for a cloud fallback: provider is not `none` and its API key is saved.
   - No fallback: build the digest with the built-in text rules. Source `template`, note explains the failure.
   - Fallback exists: sanitise the notes (see below). If sanitising blocks the send, use the built-in rules and say why. The user is never asked about something that cannot be sent.
   - Setting "use automatically" is off: return `needs-consent` with the provider, the failure and the sanitised text. The UI shows a dialog: **Send to Groq** or **Use plain template**.
   - Setting is on: send immediately.
5. A cloud call that fails (network, HTTP error, bad reply) falls back to the built-in rules with a note. Transient cloud errors (429, 500, 503, network) are retried as before: 3 attempts, 1000 and 3000 ms waits. Local calls are not retried on transport errors.

### Modes

`generate` takes `mode`: `auto` (above), `cloud` (the user said yes: skip local, sanitise, send), `template` (the user said no: built-in rules only). The renderer cannot supply AI settings; the main process reads them from the store.

### Result shape

```
{ status: "ok", source: "local" | "groq" | "gemini" | "template", note: string | null, blocks }
{ status: "needs-consent", provider, failure: { code, message }, preview: { text, chars } }
```

Failure codes: `UNREACHABLE`, `MODEL_MISSING`, `TIMEOUT`, `SERVER`, `BAD_REPLY`.

### Sanitising (cloud path only)

Applied to the five note fields, in this order:

1. **Block** (send nothing) if the notes are longer than 8000 characters, or contain something that looks like a secret: Groq, Google, `sk-`, GitHub or AWS keys, a private key header, a bearer token, `password`/`secret`/`api key` followed by `:` or `=` and a value, or a connection string with credentials (`scheme://user:pass@host`).
2. **Replace with placeholders**: emails `[EMAIL_n]`, URLs `[URL_n]`, IPv4 addresses `[IP_n]`, phone numbers `[PHONE_n]`, long token-like strings (32+ characters containing a letter and a digit) `[TOKEN_n]`.
3. **Replace the user's words**: the profile name, each word of it that is 3+ characters, and the extra words from Settings ("Words to hide from cloud services", comma separated) become `[NAME_n]`. Whole words only, case-insensitive.
4. The same original text always gets the same placeholder. After the reply, placeholders are put back (case-insensitive match; unknown placeholders are left as they are).

Dates such as `2026-10-09`, times such as `10:30` and versions such as `3.2.1` are not changed. Profile fields are never part of the prompt; they are filled in after the reply, as today.

### Local status

`ai:status` calls `GET {baseUrl}/models` with a 5 s timeout and returns `{state: "ready" | "no-server" | "no-model", detail}`. A model matches by exact id, or `name:latest` when the configured name has no tag.

### Settings

`settings.ai` becomes:

```
{ local: { baseUrl, model }, fallback: { provider: "none"|"groq"|"gemini", auto: false },
  geminiModel: "flash"|"pro", privacyTerms: "" }
```

Defaults: Ollama URL, `qwen2.5:3b-instruct`, provider `groq`, `auto` false, `flash`, empty terms. Old files (`{provider, model}`) migrate on read: the old provider becomes the fallback provider with `auto` false, and an old `flash`/`pro` model becomes `geminiModel`. A new main-owned collection `audit` holds the send log (last 200 entries); the renderer cannot write it.

### UI

- **Settings: Local AI card.** Base URL, model, status badge, Check button (saves, then checks), warnings for `-cloud` models and non-loopback URLs, and for `no-server` and `no-model` the exact text to do next (`ollama pull <model>`).
- **Settings: Cloud fallback card.** Provider, "ask each time / use automatically", Gemini model, API key (write-only, as today), Test connection, words to hide, a plain description of what is hidden, a warning on Gemini that free-tier use may be used by Google to improve its products, and the last 5 cloud sends.
- **New Digest.** Banner above the report when the source is not local: info "Generated by Groq (cloud)", or warning "AI was not used for this digest" with the reason.
- **Consent dialog.** Failure reason, provider name, the exact text that would be sent, **Send to X** / **Use plain template**.

## Rules that still hold

- The app never presses Send in Zimbra. No Zimbra password is typed or stored.
- API keys live only in the main process (`safeStorage`) and are write-only from the renderer.
- Tests and e2e use fakes only. With `DD_TEST` set, the main process gets a `fetch` that always rejects, so a developer's running Ollama is never contacted.
- No new runtime dependencies.

## Out of scope

- Bundling or auto-installing Ollama, and pulling models from inside the app (a later addition via Ollama's `/api/pull`).
- Streaming output.
- The failing "Prepare in Zimbra" selectors (see `HANDOFF.md`). They need probe output from the real Zimbra page and are independent of this work.
